# ⚽ EPL 2025-26 Analytics Dashboard

> A full-stack, team-level analytics platform for the English Premier League 2025-26 season — built as a production-style upgrade of a small leakage-free ML project into a 10-page Streamlit application.

**380 verified matches · 20 teams · 3 trained classifiers · a real chronological Elo system · honest model reporting, no fabricated numbers.**

> **Scope note:** this build is deliberately team-level only. The original brief also asked for player analytics, fantasy points, and xG approximation — those were scoped out because either the data doesn't honestly support them (xG, fantasy points require shot-location data this workbook doesn't have) or it was a conscious call to keep this pass team-only (player analytics). See the in-app [About](epl_analytics/pages/10_About.py) page for the full "built vs. skipped" breakdown.

Elo agrees with the top 3 in the table, but ranks **Bournemouth above 4 teams that finished higher in points** — a signal that their underlying results (margin of victory, opponent strength) were stronger than their points total alone shows.

### 🧩 Team clustering

- **4-tier KMeans strength grouping** on points/game and goal-difference/game: **Elite** (Arsenal, Man City), **Good** (7 teams incl. Man Utd, Liverpool, Chelsea), **Average** (9 teams), **Weak** (Burnley, Wolves).
- **5-cluster PCA playing-style map** on possession, passing, tackling, and shooting profiles, collapsing to 3 human-readable styles: *Direct / Counter-Attacking*, *Possession-Based*, and *Balanced / Mixed*.
- The first two principal components explain **72.7%** of the variance in playing style (PC1 = 58.8%, PC2 = 13.9%) — most of what separates teams' styles really does live on one main axis (roughly: direct vs. possession-based).

### 🤖 Match-outcome classifiers — the honest result

Three classifiers were trained to predict match outcome (Home / Draw / Away) on a **chronological split** (train on the first ~75% of the season, test on the final gameweeks — never the reverse):

| Model | Test Accuracy | F1 (macro) | Log Loss | 5-fold CV Accuracy |
|---|:---:|:---:|:---:|:---:|
| **Baseline** (always predict Home) | 44.8% | — | — | — |
| Logistic Regression | 27.6% | 0.274 | 1.705 | 40.5% ± 10.6% |
| Random Forest | 44.8% | 0.354 | 1.061 | 45.1% ± 8.4% |
| **XGBoost** | 41.4% | **0.396** | 1.224 | **45.6% ± 9.1%** |

**None of the three models meaningfully beats "always predict the home team wins."** Random Forest ties the baseline on raw accuracy; XGBoost falls slightly short on accuracy but has the best macro-F1 by a clear margin — it's the *only* model that actually predicts draws and away wins with any regularity (see confusion matrices on the [Model Performance](epl_analytics/pages/8_Model_Performance.py) page), which makes it the fairer model even though it isn't the more "accurate" one.

This isn't a bug — it's the correct outcome for a single-season dataset. Features are **shifted rolling averages of each team's prior 5 matches only** (never the same match's own post-game stats), which avoids target leakage but also caps how much signal is available. Real match-outcome models need multi-season Elo history, head-to-head records, and market odds — none of which exist in a single-season workbook. `epl_analytics/tests/test_data_pipeline.py` includes an explicit regression test (`test_features_no_leakage_columns`) guarding against leakage creeping back in.

**Goal regression also honestly under-performs the naive baseline:**

| Target | Model MAE | Baseline MAE (predict season mean) |
|---|:---:|:---:|
| Home goals | 1.023 | 1.006 |
| Away goals | 0.928 | 0.841 |

Train/test split: **263 train matches** (2025‑09‑13 → 2026‑03‑14) vs. **87 test matches** (2026‑03‑14 → 2026‑05‑24).

### 🔍 Feature importance

XGBoost gain-based importance is **notably flat** — the top feature (`home_goals_against_r5`) accounts for only ~3% of total gain, and the top 10 features are all within a narrow 2.0%–3.0% band. There's no single dominant predictor; recent defensive record, points form, long-ball and pass accuracy, and season-long goal difference all contribute roughly equally. This diffuseness is itself part of the story: it's further evidence that no clean signal separates outcomes on this dataset, consistent with the classifier results above. Full per-model breakdown (XGBoost gain / Random Forest impurity / SHAP) is on the [Feature Importance](epl_analytics/pages/7_Feature_Importance.py) page.

## Features

- **Home dashboard** — league KPIs, top-of-table snapshot, current Elo top 5, playing-style map.
- **League Table** — sortable/filterable standings, home/away splits, points progression, goal-difference and win-% charts.
- **Team Analytics** — per-team radar profile, goal/possession/shot trends, home vs. away split, rolling 5-match form, full match log, CSV export.
- **Team Comparison** — side-by-side stat comparison, radar overlay, Elo-based win probability.
- **Match Predictor** — pick any two teams, get outcome probabilities from all 3 trained models, a live SHAP explanation of that specific prediction, and global feature importance.
- **Elo Ratings** — full rating history and biggest single-match swings.
- **Clustering** — 4-tier strength tiers and 5-cluster playing-style map, both with plain-language explanations.
- **Feature Importance** — top-N features by XGBoost gain, Random Forest impurity, or SHAP.
- **Model Performance** — accuracy/precision/recall/F1, confusion matrices, ROC curves, learning curves, and time-series cross-validation for all 3 classifiers, plus goal-regression MAE.
- **Data Explorer** — search/sort/filter/download every dataset behind the app.
- **Dark / light theme toggle**, responsive layout, cached data loading throughout.

## Architecture

```
                    ┌─────────────────────────────┐
                    │  Soccer-Stats-...R02.xlsx    │
                    │  (raw workbook, data/raw/)   │
                    └───────────────┬───────────────┘
                                    │
                    ┌───────────────▼───────────────┐
                    │   src/data/load_data.py        │  EPL isolation, home/away join,
                    │   src/data/features.py         │  standings rebuild, leakage-safe
                    └───────────────┬───────────────┘  rolling features
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
   src/models/clustering.py  src/models/elo.py    src/models/train.py
   (strength tiers,          (chronological Elo)   (LogReg / RF / XGBoost,
   playing style PCA)                               CV, ROC, learning curves,
                                                      SHAP)
              │                     │                     │
              └─────────────────────┼─────────────────────┘
                                    ▼
                    ┌───────────────────────────────┐
                    │  data/processed/*.csv, *.json  │
                    │  models/*.pkl                  │
                    └───────────────┬───────────────┘
                                    │  (read-only, cached)
                    ┌───────────────▼───────────────┐
                    │  dashboard.py + pages/*.py      │
                    │  src/utils/{data_loader,        │
                    │  styling,charts}.py             │
                    └───────────────────────────────┘
```

The app **never retrains models or reloads the workbook at runtime** — everything under `epl_analytics/data/processed/` and `epl_analytics/models/` is generated once by `epl_analytics/scripts/build_all.py` and read through `@st.cache_data` / `@st.cache_resource` wrappers in `epl_analytics/src/utils/data_loader.py`.

## Installation

Requires **Python 3.12**.

```bash
git clone <this-repo>
cd epl_analytics
python -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
```

Place the source workbook at `epl_analytics/data/raw/Soccer-Stats-Premier-League-2025-2026_R02.xlsx` if it isn't already there (it ships with this repo).

## Usage

Build the data/model artifacts once (or whenever the source workbook changes):

```bash
python epl_analytics/scripts/build_all.py
```

Then launch the dashboard:

```bash
streamlit run epl_analytics/dashboard.py
```

Run the test suite:

```bash
pytest epl_analytics/tests/ -v
```

## Model Methodology

Match-outcome features are **shifted rolling averages of each team's prior matches only** — the raw `TeamStatsExport` possession/shots/passing columns are post-match outcomes for that same fixture, and using them directly would be target leakage (a model trained on them looks like 90%+ accuracy and is worthless for real prediction). The train/test split is **chronological** — first ~75% of the season vs. the final gameweeks — matching how the model would actually be used: predicting upcoming games from past ones, never the reverse.

See [Results & Key Findings](#results--key-findings) above for the full numeric breakdown, or the in-app [Model Performance](epl_analytics/pages/8_Model_Performance.py) and [About](epl_analytics/pages/10_About.py) pages for confusion matrices, ROC curves, and the complete data-quality writeup.

## Dashboard Walkthrough

1. **Home** — start here for the league-wide picture and KPIs.
2. **League Table → Team Analytics → Team Comparison** — drill from league-wide, to per-team, to head-to-head.
3. **Match Predictor** — pick a hypothetical fixture, see model probabilities and why the model said what it said (SHAP).
4. **Elo Ratings / Clustering / Feature Importance / Model Performance** — the analytical/ML layer, each with its own honest caveats.
5. **Data Explorer** — the underlying data, searchable and downloadable.
6. **About** — data-quality issues found and fixed, full methodology, and an honest scorecard of what was built vs. skipped from the original brief.

## Testing

`epl_analytics/tests/test_data_pipeline.py` runs **12 tests** covering data integrity and modeling correctness end to end:

- Match data shape, completeness, and valid result labels
- Standings cover all 20 teams and points reconcile with match results
- **No leakage columns** in the feature set, and features are chronologically safe (no future information leak)
- Latest-form snapshot and strength tiers cover every team
- Style clusters cover every team
- Elo ratings start at 1500 and are zero-sum conserved across all updates
- Elo table covers every team

```bash
pytest epl_analytics/tests/ -v
```

## Deployment

**Streamlit Community Cloud:** push this repo (including `epl_analytics/data/processed/` and `epl_analytics/models/`, or run `build_all.py` in a build step) to GitHub, then deploy directly from [share.streamlit.io](https://share.streamlit.io) pointing at `epl_analytics/dashboard.py`.

**Docker:**
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt && python epl_analytics/scripts/build_all.py
EXPOSE 8501
CMD ["streamlit", "run", "epl_analytics/dashboard.py", "--server.port=8501", "--server.address=0.0.0.0"]
```
